# Decision-Substrate Specification — Living Sim

**Status:** Spec approved by Joey 2026-10-09. Not implemented.
**Scope:** the generic decision service for the living simulation ("decide
with decision models, speak with something else").
**Parent docs:** `LIVING-SIM-DEEP-DIVE.md` (NPC stack, perception, tiered
brains, edge microserver); `mmo-engine-system-design/ANTI-CHEAT.md`
(telemetry replay discipline, referenced as the pattern to follow).

## 1. Purpose and non-goals

The substrate is a single swappable service that answers structured
questions for NPCs: which goal, which action, whom to trust, what to
reveal, whom to gossip about. It returns choices, probabilities, and
scores — never prose.

Non-goals:

- It does not generate dialogue. A separate renderer turns decisions into
  speech (§9).
- It does not run in the 30Hz core tick. It lives in the NPC edge
  microserver, async (§7).
- It does not replace the tiered brains (FSM/utility → behavior trees →
  GOAP-lite). The tiers consult the decider through the narrow interface
  (§3); the decider never owns the tick.

## 2. Background facts (verified 2026-10-09)

- Ollama's 0.35 release line introduced `/v1/systemone`: decision models
  returning structured choices, probabilities, and scores.
- Question types: `choice`, `noul` (probability a condition is true),
  `score`.
- Listed models: Nimble, Tev1, Clef, Clef Flash. Source:
  http://github.com/ollama/ollama/releases
- **License status: UNVERIFIED for all four models against the
  permissive-license requirement.** No model is adopted before its license
  verdict lands (§10). Until then, the substrate runs on the deterministic
  stub decider (§8).

## 3. The narrow interface

One interface. Two implementations (stub, Ollama adapter). Everything
else in the sim talks to the interface, never to a model.

```ts
// All field names and shapes are frozen at schemaVersion 1.
interface DecisionRequest {
  schemaVersion: 1;
  decisionId: string;      // uuid, generated by the caller
  npcId: string;
  tick: number;            // core tick at request time (for tie-breaks + replay)
  domain: "behavior" | "dialogue" | "social" | "quest" | "encounter";
  packId: string;          // e.g. "behavior.goal-select.v1"
  questionType: "choice" | "noul" | "score";
  stateDigest: string;     // canonical serialized state, §4 (≤ 4KB)
  candidates: Candidate[]; // for choice/score; empty for noul
  constraints: string[];   // hard rules, e.g. ["no-hostile-action-in-safe-zone"]
}

interface Candidate {
  id: string;              // stable id, e.g. "goal:patrol" or "action:flee"
  label: string;           // human-readable, for logs only
  params?: Record<string, string | number | boolean>;
}

interface DecisionResponse {
  decisionId: string;
  packId: string;
  outcome:
    | { kind: "choice"; candidateId: string; scores: Record<string, number> }
    | { kind: "noul"; probability: number }
    | { kind: "score"; scores: Record<string, number> };
  confidence: number;      // 0..1, model-reported or derived
  abstained: boolean;      // true when confidence < threshold (§6)
  fallbackUsed: "none" | "cache" | "rules" | "safe-default";
  modelId: string;         // e.g. "stub.v1" or "ollama:clef@sha"
  latencyMs: number;
}
```

Rules:

- The interface is transport-agnostic. v1 transport: HTTP POST JSON to the
  edge service (`/decide`, `/decide/batch`). The caller never imports a
  model SDK.
- `stateDigest` is opaque to the transport; its format is governed by §4.
- Every response is final for its `decisionId`. Re-asks get a new id
  (replay joins on `npcId` + `tick` + `packId`, not on id reuse).

## 4. State-serialization contract

The quality bottleneck is here: the model only knows what the digest
tells it. The contract is deterministic and bounded.

**Sources, in fixed priority order** (higher priority is truncated last):

1. Perception snapshot: current sensory-memory digest — visible entities,
   threats, points of interest (from the stimulus bus pipeline).
2. Needs vector: hunger, rest, safety, social, purpose — quantized.
3. Relationship map: per known entity — trust (−1..1), debt, last
   interaction tick, disposition tag.
4. Memory stream summary: last N salient events, newest first.
5. World facts: time of day, location id, faction standings, active
   quest ids, zone flags (safe-zone, curfew, etc.).

**Canonical form:**

- Canonical JSON: fixed key order (the order above), no whitespace.
- Floats quantized to 3 decimals. Ticks as integers. Strings as ids or
  fixed-vocabulary tags — never free prose.
- Budget: **4KB max** per digest (tunable, config not code). Truncation
  drops from the lowest priority upward: first old memory events, then
  low-salience relationships, never needs or constraints.
- `schemaVersion` stamped on every digest; the edge service rejects
  unknown versions loudly (fail fast, don't guess).

**Determinism:** identical game state → identical bytes. Golden tests lock
this: a fixture state must serialize to a checked-in byte string. Any
change to the contract bumps `schemaVersion` and re-baselines the goldens.

## 5. Question packs by domain

Packs are versioned data (JSON), not code. Each pack declares its
question type, required digest fields, confidence threshold, and fallback.

| packId | domain | type | asks | threshold* |
|---|---|---|---|---|
| `behavior.goal-select.v1` | behavior | choice | pick 1 of N goals (patrol, rest, work, flee, socialize…) | 0.60 |
| `behavior.action-score.v1` | behavior | score | score candidate actions for the active goal | 0.60 |
| `dialogue.trust.v1` | dialogue | noul | P(NPC trusts speaker X) | 0.70 |
| `dialogue.deception.v1` | dialogue | noul | P(speaker is deceiving NPC) | 0.70 |
| `dialogue.disclose.v1` | dialogue | choice | reveal / deflect / lie-by-omission / refuse | 0.70 |
| `dialogue.agree.v1` | dialogue | noul | P(NPC agrees to proposal) | 0.65 |
| `social.gossip-target.v1` | social | choice | whom to gossip to about what | 0.55 |
| `social.bond-move.v1` | social | choice | befriend / rival / ignore / reconcile | 0.55 |
| `quest.hook-fire.v1` | quest | noul | P(quest hook conditions are met for this NPC) | 0.65 |
| `quest.offer.v1` | quest | choice | offer / withhold / defer quest | 0.65 |
| `encounter.stance.v1` | encounter | choice | fight / flight / negotiate / surrender (elites+) | 0.65 |

\* Initial values; tunable per pack in config, never hardcoded. Higher
stakes (trust, deception) get higher thresholds.

Pack JSON declares: `requiredDigestFields` (the service rejects requests
missing them), `candidateSource` (where candidates come from — the
calling tier, never invented by the pack), and `fallbackPack` (the
rule-based equivalent, always present).

## 6. Confidence, abstention, tie-breaking, fallback

- **Abstention:** `confidence < pack.threshold` → `abstained: true`. An
  abstained response carries no outcome; the caller runs the fallback
  chain. Abstentions are logged (they're tuning signal).
- **Tie-breaking:** scores rounded to 4 decimals; exact ties broken by
  `hash(npcId | packId | tick | candidateId)` ascending. Deterministic,
  replayable, no RNG in the path.
- **Fallback chain** (first success wins, `fallbackUsed` records which):
  1. `none` — model answered confidently.
  2. `cache` — last confident answer for the same `(npcId, packId)` if
     younger than the pack's `cacheTtlTicks` (default: behavior 150,
     dialogue 900, social 1800 — tunable).
  3. `rules` — the pack's rule-based equivalent (the existing tier logic;
     always available, always deterministic).
  4. `safe-default` — per-domain safe action (behavior: continue current
     goal; dialogue: deflect politely; encounter: flee if threatened,
     else hold). The sim never blocks waiting for a decider.

## 7. Async batching and cadence (never the tick)

- The edge service owns a request queue. Callers (brain tiers) enqueue
  and continue with the fallback chain immediately; when the batched
  response returns, the tier may adopt it for the *next* decision cycle.
  Nothing in the 30Hz tick awaits the decider. Ever.
- **Batching:** 200ms window, max 32 requests per batch (initial,
  tunable). One model call per batch where the adapter supports it;
  otherwise sequential within the window.
- **Per-NPC cooldowns:** the same `(npcId, packId)` is not re-asked faster
  than its cooldown (behavior 5s, dialogue gates 30s, social 60s, quest
  60s, encounter 10s — tunable). Cooldown hits serve from cache or rules.
- **Priority:** player-facing NPCs (in a player's interest set) jump the
  queue; background sim NPCs wait.
- **Budgets (initial, gated):** ≤ 50 decisions/sec sustained per edge
  host; p99 latency ≤ 800ms per batch. If the adapter can't hold these on
  the provisioned hardware, the sim degrades to rules + cache
  automatically — gameplay never depends on model latency.

## 8. Implementations behind the interface

- **`stub.v1` (build first):** deterministic, table-driven. Returns canned
  outcomes per pack with fixed confidence. Exists so the entire pipeline
  — serialization, batching, fallback, telemetry, replay — is built and
  tested with zero model dependency.
- **`ollama` adapter (build after the pipeline is green):** translates
  `DecisionRequest` → `/v1/systemone` calls, maps responses back,
  enforces timeouts (per-request 500ms; a timed-out request is an
  abstention, not an error). Swapping adapters is a config change.
- The Ollama adapter is not wired to any pack until §10's license
  verdicts land. The stub is the only decider before that.

## 9. Decide vs speak (hard separation)

- The substrate returns structured decisions. A **renderer** (small chat
  model or templates — a separate decision, later) turns a
  `DecisionResponse` + dialogue context into NPC speech.
- Architectural rule, enforced by test: **renderer output never feeds
  back into game state.** Only the decider path (or the tier's own rule
  logic) mutates NPC state. A renderer regression can produce awkward
  lines; it can never produce a duplicated quest reward.
- Dialogue-gate packs (`trust`, `deception`, `disclose`, `agree`) are the
  seam: the decider resolves *what the NPC concludes*; the renderer
  resolves *how it says it*.

## 11. Build order (sequenced for cold execution)

**Phase 0 — Contract as code.** Implement `DecisionRequest` /
`DecisionResponse` types, the canonical serializer (§4), and golden
tests: fixture states → checked-in byte strings. Done when: goldens
pass, 4KB truncation behavior is tested, unknown schema versions are
rejected.

**Phase 1 — Edge skeleton + stub.** HTTP `/decide` and `/decide/batch`
on the NPC edge microserver; `stub.v1` decider; full fallback chain
(§6) with `fallbackUsed` recorded; JSONL telemetry log (§12). Done when:
a brain tier can enqueue a request, get a stub answer or a fallback,
and every path appears in the log. No model involved.

**Phase 2 — Question packs as data.** The 11 packs from §5 as versioned
JSON; pack validation (required digest fields, fallback present);
`behavior.goal-select.v1` wired end-to-end through the stub. Done when:
adding a pack is a data change with no code deploy.

**Phase 3 — Batching, cooldowns, budgets.** §7 implemented: 200ms
window, 32/batch, per-NPC cooldowns, player-facing priority, the
50/sec + p99 800ms gates with automatic degradation to rules + cache.
Done when: load test shows graceful degradation, never a tick stall.

**Phase 4 — Decide/speak split demo.** `dialogue.trust.v1` +
`dialogue.disclose.v1` through the stub; a template renderer turns
outcomes into lines; the no-feedback test (§9) passes. Done when: an NPC
can conclude "distrust + deflect" and say it differently twice without
either phrasing changing game state.

**Phase 5 — License gate → Ollama adapter → eval.** Flip §10 rows only
on verified-permissive licenses; wire the adapter to one pack
(`behavior.goal-select.v1`); build the replay harness (§12) and tune
thresholds against logged abstentions. Done when: a week's worth of
logged decisions replay deterministically and the threshold tuning doc
exists.

Each phase ends with its gate; no phase starts until the previous gate
is green. Nothing here requires Joey mid-flight except the Phase 5
license verdicts, which are his call.

## 12. Audit and telemetry

Every decision — model, cache, rules, or safe-default — appends one
JSONL record:

```json
{
  "decisionId": "...", "npcId": "...", "tick": 12345,
  "packId": "behavior.goal-select.v1", "questionType": "choice",
  "stateHash": "sha256:…", "requestHash": "sha256:…",
  "outcome": {"kind": "choice", "candidateId": "goal:patrol", "scores": {"goal:patrol": 0.81}},
  "confidence": 0.81, "abstained": false, "fallbackUsed": "none",
  "modelId": "stub.v1", "latencyMs": 3
}
```

- `stateHash` lets a reviewer refetch the exact digest bytes; `requestHash`
  covers the full request. Given the log plus the state store, any
  decision replays deterministically (same bytes → same outcome, §4, §6).
- Abstentions and fallbacks are first-class records, not errors — they
  are the tuning dataset for thresholds and pack design.
- Retention and sampling are config: keep 100% for 7 days, then sample
  to 1% (tunable). Same replay discipline as the anti-cheat audit log.

## 13. Cost/benefit gates

- Per-decision cost is measured, not assumed: p50/p99 latency and
  decisions/sec per edge host, before any gameplay depends on the model.
- The stub pipeline must be fully green before the Ollama adapter is
  even built — the fallback chain is the product; the model is an
  upgrade.
- Hardware: decision models are small by design (that is the point of
  the category), but the edge host's CPU/GPU budget still gets a number
  before Phase 5, not after.
