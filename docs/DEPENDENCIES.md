# Dependencies and licences

Every third-party thing this repo depends on, npm and vendored C++ alike:
what it is licensed under, whether it reaches a shipped artefact, and what
it obliges us (or a studio shipping a game built on the engine) to do.

Audited 2026-11-22 against `main` at `d9fe3679`. The companion output is
[`../NOTICES.md`](../NOTICES.md), the attribution file a shipped build
should carry, regenerated by `node scripts/gen-notices.mjs` (`--check`
fails when it is stale). This page is the analysis; that file is the
artefact.

**This is an engineering audit, not legal advice.** Before the engine is
licensed or sold, a lawyer should read the two MPL-2.0 items in §5 and the
licence shortlist in §6. Nothing here needs a lawyer to *act* on: every
obligation below is a notice, a file, or a packaging fix.

## 0. Short version

- **53** distinct direct third-party npm dependencies; **747** third-party
  packages resolve in the root lockfile (**191** entries in the production
  tree, **189** of them distinct `name@version`; **556** dev-only).
- **19** third-party codebases are vendored in-tree as source or binaries,
  plus **5** more bundled inside those (predicates in CDT, an SVD, a
  disjoint-set and musl-derived math in manifold, a UTF-8 decoder in
  nlohmann/json) whose notices travel with them.
- **Nothing shipped to a player is copyleft.** The whole client bundle is
  MIT, Apache-2.0 or Zlib.
- **No GPL or AGPL anywhere**, in any tree, at any depth. The one GPL-2
  project we touch (Valgrind) is present only as its two headers, which
  carry an explicit BSD-style licence for exactly this use.
- **Two MPL-2.0 items, both server-side**: the `bitecs` npm package and the
  vendored `CDT` headers compiled into `picg.node`. MPL-2.0 is per-file
  copyleft: using them unmodified inside a closed product is fine, with a
  notice and a source offer. Modifying those files is the thing to avoid.
- **LGPL appears only in dev tooling** (libvips prebuilts under `sharp`,
  all `dev` and `optional`), and never ships.
- **No dependency rules out any licence we might pick.** This corrects the
  guess recorded in [`ENGINE-CORE-SPLIT.md`](ENGINE-CORE-SPLIT.md) §5 that
  the vendored libraries would constrain the choice. They do not. They
  constrain only what a shipped build must *carry* — a notices file.
- Three real gaps, two fixed in this PR: no aggregated notices file (added),
  Apache-2.0 `flatc` binaries redistributed with no licence copy (added),
  and `physx-js-webidl` shipping to the client from a `devDependency`
  (`DEP2`, left for its own PR because it changes what installs).

## 1. What "ships" means here

Four artefacts leave this repo, and an obligation only bites where its code
actually travels:

| Lane | Artefact | Who receives it |
| --- | --- | --- |
| **S** | Region/world server: Node code plus `*.node` native addons | us, or a studio licensing the engine |
| **C** | Client bundle: browser JS and WASM | every player |
| **E** | Editor bundle | developers and designers |
| **D** | Dev- and build-only: test runners, bakers, capture tools | nobody outside our machines |

One wrinkle that matters: **the repo is public**, so anything vendored
in-tree is already being redistributed as source, whatever lane it serves.
That is what makes the `flatc` gap in §5 a real one rather than a tidiness
note — a `D`-lane binary is still a redistribution.

`/assets/` is licensed art and never ships in any lane. It is out of scope
here: this page is about code.

### 3.3 The database

The region server stores through `@surrealdb/node` 3.1.0 and
`@surrealdb/node-native` 3.3.5, both declaring **Apache-2.0** in the
lockfile, embedded in-process. `npm run db` additionally starts a
**SurrealMX** server — that is not a separate dependency, it is a storage
mode of the `surreal` CLI (`mem://…?aol=sync&snapshot=60s`,
`packages/world-server/package.json:21`). That binary is installed by the
developer from upstream and is **not** vendored here, so its terms are not
captured by this audit. If a shipped product ever bundles the `surreal`
binary rather than the embedded Node engine, check its licence then; the
embedded path we actually use is Apache-2.0.

## 4. Obligations

The two questions the brief asks are genuinely different, so they get
separate answers.

### 4.1 What binds us, shipping a closed-source commercial product

| Licence | What we must do | Where it applies |
| --- | --- | --- |
| MIT | Carry the copyright line and the permission notice with the distribution | nearly everything |
| Apache-2.0 | Carry the licence, propagate any upstream `NOTICE`, and mark files we changed | manifold, pcg-core, flatbuffers, SurrealDB, uWS, TypeScript |
| BSD-3-Clause | Carry the notice; don't use contributors' names to endorse | 2 prod packages |
| Zlib | Don't misrepresent origin; mark altered sources. **Binary distribution needs no notice** | Recast/Detour |
| BSL-1.0 | Notice required for source distribution only; **explicitly waived for machine-executable** | Clipper2 |
| **MPL-2.0** | Keep the notice, make *those files'* source available to anyone who gets the binary, and publish any modification **to those files** under MPL-2.0. Our own code stays closed | `bitecs`, CDT |

So a closed-source commercial product is clean today, with one standing
rule worth writing into CLAUDE.md if we go commercial: **never patch
`bitecs` or CDT in place — wrap them.** An unmodified MPL file costs a
notice. A modified one costs publishing that file.

Nothing here requires us to open any of our own code. Nothing here is
non-commercial, field-of-use restricted, or source-available-but-not-open.

### 4.2 What binds a studio shipping a game built on the engine

Three things, and only the third is a blocker:

1. **They inherit the attribution.** Their build contains Jolt, Recast,
   FastNoise2, manifold, Clipper2, PICG, three.js and the rest, so their
   game must carry the notices. That is exactly what
   [`../NOTICES.md`](../NOTICES.md) exists to let them do — one file to
   drop into a credits screen or an `about` page.
2. **They inherit the MPL source offer** for `bitecs` and CDT, discharged
   the same way: a notice plus a pointer to unmodified upstream source.
3. **They have no licence from us.** The repo is public with no `LICENSE`
   file, which by default means all rights reserved: a developer may read
   it, and may not ship from it. This is the only real blocker in the whole
   audit, it is not a dependency problem, and it is deliberately parked
   pending the monetisation call (see `ES1b` in
   [`ENGINE-CORE-SPLIT.md`](ENGINE-CORE-SPLIT.md)).

Also theirs to handle, and worth saying in the starter kit's README: the
art. `/assets/` never ships, the engine runs on stand-ins, and a studio
brings its own content pack. Several catalogued sources are explicitly
not redistributable (`third_party/INCORPORATION-MANIFEST.md` records
Polyfork's terms forbidding source redistribution, Quixel/Fab assets as
use-in-your-own-game but not redistribute, and Grassworks as a paid
product with unread terms). None of those are in the engine's code path.

## 6. Which licences are still open to us

All of them. No dependency excludes any option. The differences are
strategic, not legal-compatibility ones:

| Option | What it means | Fits if |
| --- | --- | --- |
| **Permissive OSS** (MIT or Apache-2.0) | Anyone may ship a closed commercial game built on the engine, and may fork it. Apache-2.0 adds an explicit patent grant and the `NOTICE` mechanism we already need; MIT is shorter and more familiar to game devs | the goal is adoption and the revenue is elsewhere (services, hosting, our own game) |
| **Weak copyleft** (MPL-2.0) | Our files stay open; a studio's own code stays closed. Matches the licence `bitecs` and CDT already use, so one rule covers the whole tree | we want contributions back without scaring studios |
| **Dual: AGPL-3.0 + commercial** | Open by default, paid licence to avoid the AGPL. Legally available to us: Apache-2.0 is one-way compatible into (A)GPL-3, MPL-2.0 §3.3 permits distribution of a larger work under a secondary licence, and MIT/Zlib/BSL impose nothing in the way | monetisation runs through licence sales, and we are ready to require CLAs from contributors |
| **Source-available** (BSL-1.1-style, with a change date) | Source stays public and readable; production use needs a paid licence until the date. Nothing we vendor objects, because we would be licensing only our own code | we want the public repo and the revenue, and accept that it is not OSS |
| **Proprietary EULA** | Most control, least adoption. The public repo would have to go private or become a curated subset | the engine is sold per studio |

Two practical notes for whenever that call is made:

- **The repo is already public.** A permissive licence makes forks legal
  from day one; a source-available or dual licence keeps that door shut.
  This is the actual decision, and it is a business one.
- **Whatever is chosen, `NOTICES.md` ships with every build.** That is true
  of all five options and is why the notices file was worth doing before
  the licence call rather than after.

## 8. What is not verified

- **Upstream activity of the vendored C++ projects.** GitHub API access in
  this container is scoped to our own repository, so "is FastNoise2 still
  maintained" could not be checked. The pins and vendoring dates in §2 are
  from the tree itself and are accurate; upstream liveness is not.
- **The `surreal` CLI binary's terms** (§3.3). Only the embedded
  `@surrealdb/node` path was checked.
- **PhysX 5.12.0's own licence.** `physx-js-webidl` declares MIT for the
  wrapper; the licence of the NVIDIA PhysX code inside the WASM was not
  read from a file in this container and must be before `DEP2` closes.
- **Whether upstreams ship `NOTICE` files** we would have to propagate
  under Apache-2.0 §4(d). No `NOTICE` exists in any vendored tree, which is
  consistent with upstream having none, but was not confirmed upstream.
- **Transitive licence fields are taken from the lockfile**, which records
  what each package declares. A package that declares MIT while containing
  something else would not be caught by this pass.
