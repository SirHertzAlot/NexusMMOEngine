Nexus engine · the 30-second tour

Living worlds, built your way.

An authoritative MMO engine for people who write code and people who don't.

A fixed 30 Hz, server-authoritative simulation with streamed 4 × 4 km worlds, an editor, and a client that only mirrors the truth. Playable end to end today, from account creation to the world.

01 · Extensible

Plug it in.

Add a system without touching the core.

Server systems, editor tools and edge services are modules with manifests. Boot orders them by after and before, and stops on a cycle with every problem listed. Native C++ comes in the same way, as an addon.

02 · Modular

Every layer on its own.

The client is never the source of truth.

The client mirrors state. Behind it sit an edge for ingress, one engine process per region, and a world server that coordinates the regions. Each one is a separate process with a framed internal transport between them.

03 · Scalable by design

More players, more regions.

Each region owns its simulation and its state.

In our stress run, one world server and 16 regions on a 4‑core box, each at 30 Hz with 500 entities and 100 players crossing borders, committed every hand-off.

04 · Fast

Measured on every change.

A fixed 30 Hz tick, with the hot paths in C++.

Jolt physics and the fan-out that decides what each player sees run natively. Each system's instruction cost is baselined under Valgrind, and a gate fails a build that gets slower.

05 · Cross-platform

Players in a browser. Servers anywhere.

One codebase on three operating systems.

The client is React Three Fiber, so it runs in a browser. The server and the tools run the same on Linux, macOS and Windows, and the native addons build with each platform's standard compiler.

06 · Designed for no-code

Content is data, so designers ship it.

Add an entry and the game takes it.

Creature rules, loot pools, spawn tables and gameplay rules are tables in the editor, and new entries need no code change. Graph editors cover procedural assets and dungeons, and terrain is edited at world scale.

07 · Git, built in

Version control in a terminal. Version control in the editor.

Designers and developers work in the same repo.

A Changes panel shows semantic diffs keyed by node id, and commits, pulls and pushes through git. Three-way merge resolves by stable ids, and soft locks keep two people out of the same document.
